## 新機能: 配線言語（試験的）

機器と電線を文字で書き、コンパイルして誤りを行番号つきで確かめられる「配線言語」を、試験的に入れました。

```
PS1  = generic.power-source.3p200v
ELB1 = mitsubishi.nv32-sv.3p(ratedCurrent=15)
MC1  = mitsubishi.s-t10.ac200v

wire KIV 2sq black {
  [R, S, T]:    PS1.[R, S, T]  -- ELB1.[1, 3, 5]
  [R1, S1, T1]: ELB1.[2, 4, 6] -- MC1.[1/L1, 3/L2, 5/L3]
}
```

- 上のバーの「**配線言語**」を押すと、いまの図面が配線言語のソースで開きます。
- 書き換えると、その場でコンパイルします。機器種別・端子 ID・電線の色などの書き間違い（近い名前の候補つき）と、配線チェックの指摘（短絡・電圧の不一致・電線の太さ不足など）が、
  書いた行の番号つきで右に出ます。指摘をクリックすると、その行を選びます。
- 「図面に反映」で図面を入れ替えます（Ctrl+Z で戻せます）。機器の位置・電線の曲がり・展開図の配置は、同じ名前の機器・同じ端子の電線から引き継ぎます。新しく書いた機器は、そのシートの機器の下に並べて置きます。
- 書けるもの: 機器の宣言とパラメータ、線番つきの電線、並んだ電線（`PS1.[R, S, T] -- ELB1.[1, 3, 5]`）、渡り配線（`A -- B -- C`）、色・太さ・種類をまとめて付ける `wire` ブロック、
  リンク（`<P24>`）、シート、PLC のユニット・マニホールドの連の装着、端子のコメント。ケーブルとチューブは、つないだ端子から自動で決まります。
- 同じ図面が JSON の約 1/8 の大きさで書けるので、生成 AI に渡す・差分を見るのにも向いています。

書き方は [docs/wiring-language.md](https://github.com/yukimasui/conneko/blob/main/docs/wiring-language.md)、見本は [examples/](https://github.com/yukimasui/conneko/tree/main/examples) にあります。
盤の実配線を文字で書いて機械が調べる言語がほかにあるかの調査は [docs/wiring-language-survey.md](https://github.com/yukimasui/conneko/blob/main/docs/wiring-language-survey.md) にまとめました。

### 知っておいてほしいこと

- 試験的な機能です。文法は、使ってみた結果で変えることがあります。
- 同じ端子と同じリンクを結ぶ、重なった電線（シートをまたぐ電線をリンクに置き換えるとできます）は、言語にすると 1 本にまとまります。
  「図面に反映」すると、接続リストの電線の本数が減ることがあります（つながり方とチェック結果は変わりません）。
- 新しく書いた機器は並べて置くだけです（配線に沿った自動配置はしません）。

### 開発者向け

リポジトリを取得していれば、コマンドラインからも使えます。

```sh
npm run cnk -- check examples/motor-starter.cnk   # コンパイルとチェック（エラーがあれば終了コード 1）
npm run cnk -- build examples/conveyor.cnk        # 図面 JSON にする
npm run cnk -- terminals mitsubishi.s-t10.ac200v  # 機器の端子 ID を調べる
```
