# 産業用ロボットの調査と実装状況

産業用ロボット（ロボット本体・ロボットコントローラー・ロボット接続ケーブル・ティーチングペンダント）の調査結果と、Conneko での実装状況をまとめる。
最初の 1 機種として、ファナックの垂直多関節ロボット LR Mate 200iD とコントローラー R-30iB Mini Plus を実装した（issue #81）。
調査は 2026-10 時点で公開されているメーカーの製品ページ・カタログと取扱説明書（の公開されている抜粋）による。
資料で確かめられなかった点は「推定」と書き、機器定義の `estimated` にも書いた（`src/devices/estimates.test.ts` が両者の一致を検査する）。

- 機器定義: `src/devices/catalog/<メーカー>-*.ts`（1 機器 1 ファイル）
- メーカーごとの共通部品: `src/devices/<メーカー>/`（ファナックは `src/devices/fanuc/`）
  - `parts.ts` 描画部品（ロゴ・ねじ・塗装色）、DC24V の受電条件、ロボットとコントローラーのコネクターの種類の組、ロボット I/O（RP1）と EE のピンの割付け
  - `peripheral-io.ts` 周辺機器 I/O（CRMA15・CRMA16）とコントローラー側の RP1（RI/RO）のピン・出力の内部経路
- ロボット接続ケーブル: `src/data/cables.ts`（両端のコネクターの種類の組。部品表に 1 本ずつ載る）
- パレットのファミリー: `src/devices/families.ts` の「ロボット」（分類 `load` で一般名称が「〜ロボット」）と「ロボットコントローラー」
- 整合性・電気チェックのテスト: `src/devices/fanuc.test.ts`

## 共通の方針

### 分類（category）とファミリー

- **ロボット本体は `load`**（モーター・アクチュエーターと同じ現場側の負荷）。一般名称は形式で「垂直多関節ロボット」「スカラロボット」「パラレルリンクロボット」のように
  「〜ロボット」にする。パレットでは「ロボット」のファミリーにまとまり、メーカー・種類で絞り込める。
- **ロボットコントローラーは `plc`**。周辺機器 I/O（PLC との受け渡し）とロボット I/O を自分の入出力として持ち、I/O 表・展開図の PLC の入出力の記号に出すため
  （IAI の SEL コントローラーと同じ扱い）。一般名称は「ロボットコントローラー」。
- ティーチングペンダントは `control`（一般名称「ティーチングペンダント」）、片側バラ線のケーブルは `terminal`（「ケーブル（片側バラ線）」のファミリー）。

### ロボットとコントローラーの接続（ロボット接続ケーブル）

- IAI のアクチュエーターとコントローラーと同じ考え方（`src/devices/iai/actuator.ts`）。コントローラー側のロボット接続コネクターはコントローラーごとの種類
  （`FANUC-R30IB-MINI-RM1` など）、ロボット側はロボットごとの種類（`FANUC-LRM200ID-RM1` など）にし、ロボット側の `mates` に適合するコントローラーの種類を書く。
  適合しない組み合わせ、RM1 と RP1 の取り違えは `connector-mismatch`（テストあり）。
- ロボット接続ケーブルは `src/data/cables.ts` に両端の種類の組で書き、ロボット側のコネクターの `defaultCable` で選ぶ。部品表に 1 本ずつ載る（テストあり）。
- RM1（動力）はピンを扱わない太いケーブル（`pins: 0`、`style: 'lan'`）。RP1 はロボット I/O を通すため 24 ピン（Conneko の中の番号。推定）にした。
  1〜8 RI1〜RI8、9〜16 RO1〜RO8、17・18 24F、19・20 0V、21〜24 パルスコーダ（扱わない）。
- どちらも `required: true`（つなぎ忘れると `connector-unconnected`）。ティーチングペンダントのコネクターは、ペンダント側だけ `required`。

### 周辺機器 I/O（PLC との受け渡し）

- R-30iB Mini Plus の CRMA15・CRMA16 は 50 極（A01〜A25・B01〜B25、2.54mm ピッチ）で、MIL 50 極のフラットケーブル・変換端子台
  （`generic.mil-terminal-block.50p`）とつながる。ピンID は MIL 標準の千鳥番号（A_k → 2k−1、B_k → 2k）、印字はラベルの括弧に残す（`DI101（A05）`）。
- 入力は `signal: { dir: 'in', kind: 'dc', common: SDICOM のピン }`。SDICOM を +24V につなぐとプラスコモン（PLC の NPN 出力で駆動）、0V につなぐとマイナスコモン。
  PLC の NPN 出力をマイナスコモンの入力につなぐと `signal-polarity`（テストあり）。
- 出力はソース形（`kind: 'pnp'`）で、出力 → DOSRC（出力の電源）への `switch: 'output'` の内部経路。DOSRC に +24V を供給しないと負荷に電源が来ない（テストあり）。
- 入出力番号はラベルの先頭の語（`DI101`、`DO101`、`UI1`、`UO1`）。周辺機器（UOP）の信号は `UI1 *IMSTP` のように UOP 番号と信号名を並べた。
- コントローラーの I/O 表に DI/DO/UI/UO/RI/RO が並び、つないだ PLC の I/O 表にもコントローラーのピンが接続先として出る（テストあり）。

### ロボット I/O（エンドエフェクタ用コネクター EE）

- LR Mate 200iD の EE（12 ピン）は 1〜6 RI1〜RI6、7 RO7、8 RO8、9・10 +24V、11・12 0V（推定）。ロボットの中の配線（`links`）で RP1 の同じ信号のピンへ通じ、
  ロボット接続ケーブル RP1 でコントローラーの RI・RO・24F・0V につながる。EE ケーブル（`fanuc.ee-cable`）の芯線につないだセンサー・電磁弁は、電源のチェックが効き、
  コントローラーの I/O 表の RI・RO に出る（テストあり）。
- RI のコモンの極性は資料で確かめられなかったため、`common` を書かない（NPN/PNP の指摘をしない）。RO はソース形（+24V を出す）。

### 安全信号

- 外部非常停止 EES1→EES11・EES2→EES21、安全柵 EAS1→EAS11・EAS2→EAS21 を 2 チャンネルの安全入力の組（`safetyChannels`、mode `nc-nc`）にした。
  出力側（EES1 など）は `supply.kind: 'test'`＋`function: 'test-output'`、入力側（EES11 など）は `function: 'safety-input'`。
  片側だけの配線は `safety-channel-partial`（エラー）、チャンネルの取り違えは `safety-channel-cross`、ループに a 接点を入れると `estop-not-nc`（テストあり）。
  使わないときに短絡線でつないでも指摘しない。
- ESPB1-ESPB11・ESPB2-ESPB21（非常停止ボタンの接点出力。推定）は `{ switch: 'NC', safetyContact: true }`（機器の外のもの＝ティーチングペンダントの非常停止ボタンで開く b 接点）。
  セーフティリレーの入力のループに入れても指摘しない（テストあり）。`schematic.actuator: 'emergency'` で展開図では非常停止の b 接点の記号になる。
- 安全性能（PL・カテゴリ）は資料で確かめられなかったため書いていない。

### エア

- ロボットの中を通るエアの配管は、ベースの供給口（`kind: 'in'`）とアームの出口（`kind: 'out'`）を向きのない `airLinks` でつないだ（電磁弁なしの仕様）。
  エア源から供給口へチューブをつなぐと、出口の先の電磁弁まで圧力が届く。使わないことが多いので、ポートは `optional`。

### 展開図

- コントローラーは `plc` なので、周辺機器 I/O とロボット I/O は PLC の入力・出力の記号（出力はソース形の記号）になる。端子番号は印字（A05 など）。
- ESPB は非常停止の b 接点の記号。安全入力（EES・EAS）は機器の箱の端子になる。

## 確かめられなかったこと

- R-30iB Mini Plus の周辺機器 I/O の点数とピンの並び（R-30iB Mate のメインボードの資料の一部と、公開されている断片から推定）。
  Mini Plus を CRMC15・CRMC16（入力 20 点・出力 16 点）とする第三者の記事もあり、一次資料で確かめる必要がある。
- Mini Plus のロボット接続ケーブルのコントローラー側の形（RM1・RP1 の 2 本か、RMP の 1 本か）。資料には RMP（動力とパルスコーダを 1 本にまとめたもの）とする記述もある。
  Conneko では issue #81 の方針どおり RM1・RP1 の 2 本にした。
- 安全信号の端子台の名前・位置（R-30iB Mate では TBOP20 など）と、ESPB の有無。
- LR Mate 200iD の標準の塗装色はファナックイエロー（白塗装はクリーン仕様 /7C などで、カタログの注記による）。J2〜J6 の動作範囲・速度は確かめた資料がないため説明に書いていない。
- ロボット I/O の入力（RI）のコモンの極性、出力（RO・DO）の定格電流。

## ほかのメーカー・形式を足すとき

- ロボット本体: 1 機種 1 ファイル（`<メーカー>-<型式>.ts`）。一般名称は形式で「垂直多関節ロボット」「スカラロボット」「パラレルリンクロボット」とし、分類は `load`。
  盤外の大型機器なので、横から見た姿を 1mm ≒ 0.3px 程度に縮めて描く。
- コントローラー: 一般名称「ロボットコントローラー」、分類 `plc`。周辺機器 I/O は `signal`（入力）と `switch: 'output'`（出力）、安全信号は `safetyChannels` で書く。
- ロボット接続: メーカーの共通部品（`src/devices/<メーカー>/parts.ts`）にコネクターの種類の組を書き、ロボット側の `mates` と `src/data/cables.ts` のケーブルの組を足す。
  1 台のコントローラーに複数のロボットが適合する場合は、それぞれのロボットの `mates` にコントローラーの種類を書く。
- この表に行を足すときは、メーカーの見出し行（**安川電機**・**デンソーウェーブ**・**不二越**・**川崎重工業** など）を足し、推定の値は「推定」と書く。
- 候補（未調査）: 安川電機 MOTOMAN（GP シリーズ・MotoMINI と YRC1000micro）、デンソーウェーブ（VS / COBOTTA と RC8A / RC9）、不二越（MZ シリーズと CFD）、
  川崎重工業（RS シリーズと F60 / E01）、パラレルリンクロボット（ファナック M-1iA など）、スカラロボット。

### ロボットとコントローラーの接続

- YRC1000micro はマニピュレータとの動力・信号を 1 本のケーブルでつなぐ（安川電機の掲載の「For manipulator power/signals (-X1)」）。Conneko では両端を X1 とし、

- ファナックのコントローラー・ロボットとはつながらない（`connector-mismatch`。テストあり）。ロボットの X1 から引くと候補は YRC1000micro だけ（テストあり）。
- 部品表にマニピュレータケーブルが 1 本載る（テストあり）。

### 入出力（PLC との受け渡し）

- 点数は仕様どおり（専用入力 7・専用出力 1・汎用入力 8・汎用出力 8）。コネクタの形とピンの並びは確かめられなかったため、Conneko では MIL 40 極とし、
  1・2 +24VU、3・4 0VU、5〜11 専用入力 SIN1〜SIN7、12〜19 汎用入力 IN01〜IN08、21〜28 汎用出力 OUT01〜OUT08、29 専用出力 SOUT1、37・38 +24VU、39・40 0VU とした（推定）。
  MIL 40 極の変換端子台（`generic.mil-terminal-block.40p`）につなぐと、I/O 表に入力 15 点・出力 9 点が並び、つないだ PLC の出力も接続先として出る（テストあり）。
- 入力は +24VU（内部電源）を共通にしたプラスコモン（`signal.common` が +24VU のピン）。PLC の NPN 出力で駆動でき、PNP のセンサーをつなぐと `signal-polarity`（テストあり）。
- 出力は NPN（0VU への `switch: 'output'`、0.1A）。負荷を +24VU と出力の間につなぐ（テストあり）。
- 入出力の番号はラベルの先頭の語（`IN01`、`OUT01`、`SIN1`、`SOUT1`）。専用入出力の名前（外部起動・外部ホールドなど）は YRC1000 の専用入力からの推定。

### 内部ユーザ配線（ハンドへの配線）

- GP7 の腕の中を通る内部ユーザ配線は、ベース側のコネクタ BC と U アーム側のコネクタ UC の同じ番号のピンがつながる（`links`）。
  両端にユーザケーブル（`yaskawa.gp7-user-cable`、片側バラ線）を差すと、ハンドのセンサーの出力が腕の中を通ってコントローラーの IN01 に届き、I/O 表にセンサーが出る（テストあり）。
- ファナックの LR Mate と違い、ロボットの I/O をコントローラーの中で受ける専用の信号（RI/RO）はない。ハンドの信号はコントローラーの汎用入出力か PLC へ自分で配線する。
- エアはベースの供給口（Rc1/4）から U アームの出口へ向きのない `airLinks` でつないだ。

### 安全信号

- 外部非常停止 EXESP1+→EXESP1-・EXESP2+→EXESP2-、安全柵 SAF_F1+→SAF_F1-・SAF_F2+→SAF_F2- を 2 チャンネルの安全入力の組（`safetyChannels`、mode `nc-nc`）にした。
  ＋側は `supply.kind: 'test'`＋`function: 'test-output'`、−側は `function: 'safety-input'`。片側だけの配線は `safety-channel-partial`、チャンネルの取り違えは `safety-channel-cross`、
  ループに a 接点を入れると `estop-not-nc`（テストあり）。使わないときに短絡線でつないでも指摘しない。
- 実機では安全信号のコネクタ（HC シリーズの資料では外部非常停止を Safety コネクタの 4-14・5-15 ピン）にあり、出荷時はダミーコネクタのジャンパでつながっている。
  Conneko では配線しやすいようにねじ端子として描き、端子の名前は YRC1000 の安全信号の名前から推定した。
- ペンダントの非常停止ボタンの接点を外へ取り出す端子（ファナックの ESPB にあたるもの）と、外部イネーブルスイッチの入力は表していない。安全性能（PL・カテゴリ）は書いていない。

### 確かめられなかったこと

- YRC1000micro の入出力のコネクタの形・ピンの並び、安全信号のコネクタのピンの並び、電源入力の端子の形。
- GP7 の内部ユーザ配線の芯数・コネクタ名、エアのねじ、マニピュレータケーブルのロボット側のコネクタ名（Conneko では X1）。
- GP7 の本体質量（34kg とする資料と 37kg とする資料がある）、J1〜J6 の動作範囲・速度（説明に書いていない）、電源容量。

### ロボットとコントローラーの接続

- どのメーカーも、ロボット側のコネクターの種類をロボットごと、コントローラー側をコントローラーごとにし、ロボット側の `mates` に適合するコントローラーを書いた。
  2 本の取り違え（MOTOR と ENCODER、X1 と X2、RM1 と RP1）、ほかのメーカー・ほかの機種のコントローラーは `connector-mismatch`、つなぎ忘れは両方に `connector-unconnected`（テストあり）。
- ファナックは LR Mate 200iD ⇔ R-30iB Mini Plus、SR-3iA ⇔ R-30iB Compact Plus、M-1iA ⇔ R-30iB Mate Plus の組だけがつながる（テストあり）。
  実機では SR-3iA/U などは R-30iB Mate Plus にもつなげ、LR Mate も Mate Plus につなげるが、Conneko では 1 機種 1 コントローラーにした（簡略化）。
- iPendant はファナックの 3 つのコントローラーの TP に共通（コネクターの種類が同じ）。

### デンソーウェーブ RC8A のミニ I/O・ハンド I/O・安全 I/O

- ミニ I/O は実機ではミニ I/O のケーブル（安全 I/O の芯線も含む）でつなぐ。Conneko では入出力を MIL 50 極のコネクター（MIL 50 極の変換端子台とつながる）とし、
  1・2 +24V、3〜10 IN0〜IN7、11〜24 システム入力 SI0〜SI13、25〜32 OUT0〜OUT7、33〜48 システム出力 SO0〜SO15、49・50 0V とした（推定）。
  システム出力は製品ページの 18 点と RC8 のデータシートの 16 点が食い違うため、50 極に収まる 16 点にした。
- NPN 仕様: 入力は +24V を共通にしたプラスコモン（PLC の NPN 出力で駆動でき、PNP のセンサーは `signal-polarity`）、出力は NPN（0V への `switch: 'output'`）。テストあり。
- ハンド I/O（入力 8・出力 8）は、VS-060 の第 3 軸のケーシングのハンド I/O コネクターから、ロボットの中の配線とロボット接続ケーブル（エンコーダー）を通ってコントローラーへ戻るとした
  （ファナックの EE・RP1 と同じ扱い。推定）。ハンド I/O ケーブルにつないだセンサー・リレーがコントローラーの I/O 表の HI0・HO0 に出る（テストあり）。
- 安全 I/O は、デンソーの資料の 3 つの安全回路（非常停止・防護停止・自動運転許可）を、ES1±・ES2±、PS1±・PS2±、EA1±・EA2± のねじ端子として描いた（端子の名前は推定）。
  2 チャンネルの安全入力の組（`nc-nc`）で、片側だけ・取り違え・a 接点を指摘する（テストあり）。安全性能（カテゴリー 4・PL e）は説明に書いたが `safety` には書いていない。

### 川崎重工業 E01 の汎用入出力・安全信号

- 汎用 I/O ボードの入力 32 点・出力 32 点を、D-sub 37 ピンのコネクター 2 つ（入力 CN2・出力 CN4。名前は第三者の資料による推定）とした。
  ピンは 1〜32 が入出力、33・34 +24V、35〜37 0V（推定）。入出力の番号は AS 言語の信号番号（入力 1001〜、出力 1〜）にした（`IN1001`、`OUT1`）。
- NPN 仕様（PNP も選べるが Conneko では NPN だけ）。D-sub 37 ピンの I/O ケーブル（`kawasaki.io-cable-d37`、片側バラ線）でつなぐと、I/O 表に入出力が並び、つないだ PLC の出力・リレーが接続先に出る（テストあり）。
- 外部モーター電源 ON・外部サイクルスタート・外部ホールドなどの専用信号は、実機では設定で汎用入出力に割り当てる。Conneko では割り当てを表していない。
- RS007N の腕の中の信号線（UB ⇔ UA）は安川電機 GP7 の内部ユーザ配線と同じ扱い。ハンドのセンサーを信号線ケーブルでベース側から E01 の入力へつなぐと I/O 表に出る（テストあり）。
- 安全信号: 外部非常停止 EMS1±・EMS2±、安全柵 SFS1±・SFS2±（2 チャンネル、`nc-nc`。端子の名前は推定）。

### ファナック SR-3iA・M-1iA と R-30iB Compact Plus・Mate Plus

- コントローラーの周辺機器 I/O（CRMA15・CRMA16）・ロボット I/O（RP1）・安全信号（EES・EAS）は R-30iB Mini Plus と同じ定義を使った（`src/devices/fanuc/peripheral-io.ts`）。
  Mate Plus は保守説明書 B-83525 が直接の資料。Compact Plus の周辺機器 I/O は資料で確かめられず、Mini Plus と同じと推定した。ESPB（ペンダントの非常停止の接点出力）は描いていない。
- SR-3iA の EE は LR Mate 200iD と同じ 12 ピンの割付けとし、既存の EE ケーブル（`fanuc.ee-cable`）がつながる（テストあり）。電磁弁内蔵の仕様は表していない。
- M-1iA は RM1・RP1 だけ。手首のハンドへの配線・エアは表していない（簡略化）。
- 絵: SR-3iA はベースの上の水平な 2 本の腕とその先を上下に貫くシャフト（横から見た姿）、M-1iA は架台の梁に吊った本体と 3 本の上腕・平行な 2 本ずつのロッド・可動板（正面から見た姿）にして、
  ひと目でスカラ・パラレルリンクと分かるようにした。一般名称は「スカラロボット」「パラレルリンクロボット」で、どちらも「ロボット」のファミリーに入る。
