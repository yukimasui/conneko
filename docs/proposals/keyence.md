# KEYENCE 機器の実装で足りなかった表現（提案）

KEYENCE の PLC・センサーを実装していて、現在の型（`src/devices/types.ts`）やチェック（`src/check/checkDiagram.ts`）では
表現しきれなかった点をまとめる。型・アプリ本体は変更していない（機器側の工夫で回避したものは「現状の回避策」に書いた）。

## 1. パラメータで変わる端子・ピンの名前（label）

- **何が足りないか**: `svg` は関数にできるが、`TerminalDef.label` / `PinDef.label` は固定文字列。
  - I/O ユニットのリレー番号は装着位置（先頭リレー番号）で決まる（例: 先頭 R1000 なら IN 000 → R1000）。
  - センサーの出力形式（NPN/PNP）をパラメータで選んでも、出力線のラベルに反映できない。
- **欲しい型**: `label?: string | ((params: ParamValues) => string)`、または `DeviceDefinition.pins` / `terminals` 自体を
  `(params) => ...` で返せるようにする。I/O ユニットには `headRelay`（先頭リレー番号）パラメータを持たせ、
  ラベルを `R${head + offset}` で作れるとよい。
- **該当機器**: KV-B16XC など全 I/O ユニット、KV-NC 系、PZ-G・FS-N・LV-N・GT2 など NPN/PNP 切換のセンサー。
- **現状の回避策**: ラベルは相対番号（`IN 000 (No.1)`）にして、description に「先頭リレー番号からの相対番号」と書いた。

## 2. パラメータで変わる受電条件（accepts の電圧範囲）

- **何が足りないか**: `AcceptSpec.minVoltage` / `maxVoltage` は数値のみで、`NumOrParam` を使えない。
- **欲しい型**: `minVoltage: NumOrParam`、`maxVoltage: NumOrParam`（または accepts をパラメータごとに切り替える仕組み）。
- **該当機器**: 入力ユニットの入力モード（DC24V / DC5V 切替: KV-B16XC、KV-C16XTD、KV-SIR32XT、KV-NC16EX など）。
- **現状の回避策**: 入力 COM は DC4.5〜26.4V を一律に許容（12V を誤って入れても検出できない）。

## 3. 出力の ON/OFF（スイッチ）を表す内部経路

- **何が足りないか**: `links` は常に導通（接点は「閉」）。トランジスタ出力・リレー出力を「閉」とみなすと、
  シンク出力に負荷をつないだときに負荷へ 0V が届き `no-power` が出なくて便利な一方、
  - 全出力が COM と同電位グループになり、出力どうしが同じネットとして扱われる。
  - 出力が OFF のときの状態（たとえば出力にセンサーの + を直結する誤配線が、ON 時には短絡になる）を区別できない。
- **欲しい型**: `InternalLink.switch?: 'no' | 'nc'` のような「開閉する経路」の印。チェック側で
  「閉とみなして電源条件を確認」「閉にしたら異極がつながる（短絡）なら警告」など、通常の導通と分けて扱えるとよい。
- **該当機器**: すべての出力ユニット（KV-B16TD、KV-C32TD、KV-B16RC、KV-B8RC、KV-NC16ETE、KV-TF40 の OUT/ALM、KV-SH04PL の SVON など）。
- **現状の回避策**: 出力点と COM を通常の `links` でつないだ（description に「図面上は出力 ON とみなしてチェックする」と明記）。

## 4. 信号の種類（NPN/PNP、無電圧接点、アナログ）と入力回路の相性チェック

- **何が足りないか**: 出力線・入力線は `role: 'signal'` で電源チェックの対象外。そのため、
  - NPN 出力のセンサーを、COM を 0V にした（マイナスコモンの）PLC 入力につなぐ誤り
  - アナログ出力（4〜20mA）を DC 入力ユニットにつなぐ誤り
  - 外部入力（無電圧入力）に +24V を直接入れる誤り
  を検出できない。
- **欲しい型**: `TerminalDef.signal?: { kind: 'npn' | 'pnp' | 'dry' | 'analog-v' | 'analog-i' | 'pulse-ld' | 'comm'; ... }` と、
  入力側に `sink?: 'plus-common' | 'minus-common' | 'either'`（COM の配線から決まる）。
  同じネットにある出力と入力の種類の組み合わせをチェックできるとよい。
- **該当機器**: 全センサー（PZ-G、EZ、FS-N、LV-N、IL、GT2、GP-M、FD-Q、LR-Z）、入力ユニット、アナログユニット、KV-SH04PL（ラインドライバ）。

## 5. 2線式センサー（漏れ電流・直列接続）

- **何が足りないか**: 2線式近接センサー（EV シリーズ）は電源線を持たず、PLC 入力回路に直列に入る。
  現状の型では 2 本とも `signal` にするしかなく、「片方を入力端子、もう片方を電源（COM の反対極）へ」という配線ルールを表せない。
- **欲しい型**: 4 の信号種類に `'2wire'` を加え、2 本のうち一方が入力端子、もう一方が電源に届いていることをチェックする。
- **該当機器**: `keyence.ev`。

## 6. 拡張ユニットの連結（バス）と内部電源の消費

- **何が足りないか**: KV シリーズの拡張ユニットは CPU（または KV-EC01）の右に連結し、内部電源（5V 系）を CPU から受ける。
  連結関係と消費電流の合計（CPU の最大 3.2A / 3.4A、KV-EC01 の 1.8A）を表せない。
  また、拡張ユニットのリレー番号は連結順で決まる（1 の先頭リレー番号）。
- **欲しい型**: `role: 'bus'`（左右の連結コネクタ）と `busConsumption`（内部消費電流）。
  隣接配置した機器どうしをバスでつなぎ、親（CPU）の `loadCurrent` に子の消費を加算する。
- **該当機器**: KV-X550 / KV-8000 と全拡張ユニット、KV-EC01 と KV-NC□□E。
- **現状の回避策**: CPU・KV-EC01 の消費電流を `params`（consumption）で手動選択。

## 7. コネクタ付きセンサーと接続ケーブル（M8 / M12 / e-CON）

- **何が足りないか**: M12・M8 コネクタのセンサーは、センサー本体と接続ケーブル（別売、線色付きのバラ線）が別部品だが、
  現状のコネクタ（`role: 'connector'`）は「同じ種類のコネクタどうしをケーブルでつなぐ」ためのもので、
  片側がバラ線のケーブル（XC-H34D のような片側バラ線ハーネスも同様）を表せない。
- **欲しい型**: ケーブルを機器として置けるようにする（片端がコネクタ、もう片端が線色ごとの端子）か、
  `connector.kind` に `'M12-4'` / `'M8-4'` / `'ECON4'` を追加し、`ConnectorSpec.pinColors?: Record<number, WireColor>` を持たせて
  「バラ線ケーブル」用のデバイスを共通化する。
- **該当機器**: GP-M、FD-Q、LR-Z（現状はケーブル付きの姿で描き、線色の端子を本体に持たせた）、XC-H34D / XC-H40D（片側バラ線ハーネス）。

## 8. 通信ポートのプロトコル

- **何が足りないか**: Ethernet と EtherCAT はどちらも RJ-45（kind `'RJ45'`）なので、EtherCAT ポートを社内 LAN のスイッチにつなぐ誤りや、
  EtherNet/IP しか話さない機器と EtherCAT マスタをつなぐ誤りを区別できない。
- **欲しい型**: `ConnectorSpec.protocols?: string[]`（例: `['ethernet', 'ethernet-ip']`、`['ethercat']`）で、
  ケーブルでつないだ両端に共通のプロトコルがなければ警告。
- **該当機器**: KV-X550（PORT1/2 = Ethernet、PORT3 = EtherCAT）、KV-XH16EC、KV-EC01、KV-XLE02、VT5。
  MECHATROLINK-III は形状も違うので kind を `'MECHATROLINK3'` とした。

## 9. 「正面を向いた」コネクタの向き

- **何が足りないか**: `side` は上下左右のみ。MIL コネクタや RJ-45 は機器の正面（図の手前方向）に差すため、
  縦長のコネクタでも `side: 'bottom'` としてケーブルを下へ出している（コネクタ幅は本体幅程度に縮めて指定）。
- **欲しい型**: `side: 'front'`（手前に出てから下へ曲がる描画）か、`connector.orientation: 'vertical' | 'horizontal'`。
- **該当機器**: KV-C32XC 系・KV-C64 系・KV-SIR32XT・KV-SH04PL・KV-NC 系の MIL コネクタ、RJ-45 ポート全般。

## 10. 電源の許容電圧が「定格 ±%」の機器と、表示用の端子番号

- 細かい点として、`TerminalDef` に印字（端子台の番号）と機能名を別々に持てると AI に渡す情報が整理しやすい
  （例: XC-T34B1 の端子 `17` は「印字 17、機能は接続先の COM0」）。現在は `label` に両方を書いている。
