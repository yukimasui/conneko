# 展開図エディタと DXF 出力の設計（issue #12）

Conneko の概念図（機器と電線）の接続情報から、JIS C 0617（IEC 60617）の記号で描いた展開接続図などを起こし、
アプリ上で配置を確認・調整してから DXF に書き出すための設計。まだ実装前で、ここで決めた内容を土台に段階的に作る。

## 目的

- 接続情報だけから機械的に DXF を作ると、記号の並びや線の取り回しが人の読む図にならず、CAD での手直しが多くなる。
- そこで、DXF にする前に **アプリ上で記号の配置をプレビュー・操作** できるようにし、手直しを大幅に減らす。
- 接続は概念図が正（唯一の情報源）とし、展開図は **配置だけ** を持つ。展開図の上で配線を足したり消したりはしないので、
  概念図と展開図の接続が食い違うことはない。

## 対象とする図面

| 図面 | 内容 | 配置の自由度 |
|---|---|---|
| 展開接続図（シーケンス図） | 左右に立てた縦の母線の間に、接点・コイル・負荷を横向きの段（行）として上から並べる（PLC のラダー図と同じ形）。主回路と制御回路 | 大きい（エディタの主な対象） |
| I/O 割付図 | PLC の入出力点ごとに 1 行。入力は接点・センサー → 入力点、出力は出力点 → 負荷 | 小さい（自動生成 + 微調整） |
| 端子台接続図 | 端子台ごとに端子番号・線番・盤内側/盤外側の行き先を並べる | ほぼなし（自動生成） |

盤内器具配置図（外形の実寸配置）は対象外とする。

## 全体の構成

```
概念図（devices / wires）
   │  要素の切り出し（機器定義の terminals / links / pins から）
   ▼
要素（MC1 のコイル、MC1 の 13-14 a 接点、ELB1 の 3 極 …）
   │  展開図エディタで配置（Conneko の別モード。配置は図面 JSON の schematic に保存）
   ▼
展開図 JSON（conneko-schematic。座標・記号・線をすべて解決済み。mm 単位）
   │  tools/dxf の Python スクリプト（ezdxf）
   ▼
DXF
```

- エディタは Conneko の中の別モード（概念図 / 展開図の切り替え）。単一 HTML のまま動く。
- Python スクリプトは **解決済みの図形を DXF に写すだけ** の薄い変換にする。機器定義・接続・記号の形はすべてアプリ側が持ち、
  記号の形（図形の定義）も展開図 JSON に含めて渡す。これにより
  - アプリのプレビューと DXF の見た目が一致する（同じ図形定義から描く）。
  - 記号の形を直すのは TypeScript 側の 1 か所だけで済む。
  - 将来アプリから直接 DXF を出す場合も、Python の処理をそのまま TypeScript に移すだけで済む。
- Python スクリプトはこのリポジトリの `tools/dxf/` に置く（配布する HTML には含めない補助ツール）。

## 要素（記号の単位）

展開図では 1 台の機器が複数の記号に分かれる（電磁接触器ならコイル・主接点・補助接点が別々の場所に描かれる）。
この記号の単位を **要素** と呼び、機器定義から次のように切り出す。

| 要素 | 切り出し元 | 記号 |
|---|---|---|
| コイル | `role: 'input'` の端子の組で、機器が電磁接触器・リレー類のもの（例: `A1`/`A2`） | コイル |
| a 接点 / b 接点 | `links` の `switch: 'NO'` / `'NC'` | a 接点 / b 接点（操作の種類で押しボタン・非常停止・リミット・熱動などに描き分け） |
| c 接点 | 共通の端子を持つ `switch: 'NC'` と `'NO'` の組（汎用リレーの 9-1/9-5 など） | c 接点 |
| 主接点 | 電磁接触器の `role: 'line'` → `'load'` の `switch: 'NO'`（極をまとめて 1 要素） | 多極の a 接点 |
| 遮断器の極 | `protects: true` の経路（極をまとめて 1 要素） | 配線用遮断器・漏電遮断器・サーキットプロテクタ |
| 熱動素子 | サーマルリレーの主回路の経路 | 熱動素子 |
| PLC 入力点 / 出力点 | `signal.dir: 'in'` のピン・端子 / `switch: 'output'` の経路 | 入力・出力の枠（I/O 番号つき） |
| 端子 | 端子台の常時導通の経路でつながった端子の組（上下のネジなど） | 端子記号（○と端子番号） |
| 負荷 | モーター・表示灯など | 電動機・表示灯など |
| 接地 | `role: 'ground'` の端子 | 接地 |
| 箱 | 上のどれにも当たらない機器（電源ユニット、IAI のコントローラーなど） | 端子を並べた四角（端子名つき） |

- 実装は `src/schematic/elements.ts`（`deviceElements()`）。切り出しの順と細かな決まりはそのファイルの先頭のコメントにある。
- 要素の ID は `<機器名>:<キー>`。キーは端子 ID から作り、機器定義の端子 ID が変わらない限り変わらない
  （例: `MC1:A1-A2`、`MC1:13-14`、`ELB1:main`、`TB1:1a`、`PLC1:CN1#1`）。
- 箱は、ネジ端子の残りで 1 つ、コネクタのピンの残りはコネクタごとに 1 つ作る（PLC のコモン・電源など）。
- 機器の種類（`category`）や端子だけでは、接点の操作の種類（押しボタンか、リミットスイッチか…）やコイルかどうかを決めきれない。
  そこで機器定義に任意の `schematic` を書いて自動の切り出しを補う（書き方は [device-authoring.md](device-authoring.md)）。

  ```ts
  // 例: 照光式の非常停止。接点は非常停止の記号、X1-X2 は表示灯
  schematic: { actuator: 'emergency', elements: [{ kind: 'lamp', terminals: ['X1', 'X2'] }] },
  // 例: 漏電遮断器
  schematic: { earthLeakage: true },
  ```

- `src/schematic/elements.test.ts` で全機器・全パラメータの切り出しを検査する（キーの重複・端子の重複・取りこぼし・記号の端子との対応）。

### 記号ライブラリ

`src/schematic/symbols.ts`。すべて左から右へ流れる横向き（ラダー図の段に置く向き）で、縦に使うときは配置で回転する。
単位は mm、端子は 2.5mm の格子に乗せる。2 端子の記号は端子を (0, 0) と (10, 0) に、多極の記号は極を 5mm 間隔で下へ並べる。

| 記号 ID | 記号 |
|---|---|
| `contact-no` / `contact-nc` / `contact-c` | a 接点 / b 接点 / c 接点（端子 1 が共通、2 が b 接点側、3 が a 接点側） |
| `contact-{no,nc,c}-{pushbutton,emergency,pull,limit,thermal}` | 操作の種類つきの接点（押しボタン・非常停止・引き操作・リミットスイッチ・熱動） |
| `coil` / `lamp` | コイル（四角）/ 表示灯 |
| `motor-3p` / `motor-1p` | 電動機 |
| `breaker-Np` / `elb-Np` / `contactor-Np` / `thermal-Np`（N = 1〜4） | 遮断器 / 漏電遮断器 / 電磁接触器の主接点 / 熱動素子 |
| `terminal` / `ground` | 端子 / 接地 |
| `plc-in` / `plc-out` | PLC の入力 / 出力（枠の中に入出力番号） |
| `box_<機器種別>_<キー>_<ハッシュ>` | 箱（機器ごとに作る） |

記号の属性: `TAG`（機器名）、`T1`, `T2`…（記号の端子 1, 2… の端子番号）、`XREF`（接点の所在）、`ADDR`（入出力番号）、`COMMENT`。
全記号の一覧は `npm run schematic-sample -- out.json --png` で画像にできる（`tools/dxf/samples/sample.json` の 1 枚目）。

## 接続（展開図の線）

実装は `src/schematic/layout.ts`（`buildSchematic()`）。

- **網**: 電線・ケーブル（両端の同じ番号のピン）・同じ名前のリンクでつながった端子を 1 つの網とする。
  どの展開図にも置いていない機器の中の常時導通の経路（端子台の上下のネジ、電源ユニットの +V1-+V2 など）は素通しにする。
  置いた要素の中の導通は記号として描くのでまとめない。開閉する経路（接点・PLC の出力）は素通しにしない。
- **線**: 網ごとに、置いた端子どうしを最小全域木（縦横の距離）でつなぐ。端子からまっすぐ出してから L 字に曲げ、
  出す長さ（2.5〜15mm）と曲げ方の組み合わせのうち、記号を横切らず、別の網の線と重ならない・T 字に触れない・交差しないものを選ぶ
  （並んだ極から枝を出しても線が重ならない）。同じ高さで向かい合う端子はまっすぐつなぐ。3 本以上が集まる点に黒丸を付ける。
- **母線**: シートの左右に縦の母線を立て、その間に段を横向きに上から並べる（PLC のラダー図と同じ形）。
  シートごとに左右の母線にする電位（`機器名.端子ID`）を選ぶと、その網につながる端子は横にまっすぐ母線へ引き出す
  （母線と反対を向いた端子など、まっすぐだと記号を横切る場合は記号の下か上を回り込む）。母線は先に引き、ほかの線はこれを避ける。
- **線番**: 網の電線の線番を、いちばん長い横の区間の上に書く（母線への引き出しはそれぞれに書く）。
- **別のシート**: 同じ網の端子が別のシートにもあれば、端子の先に `→行番号` を書く。
- 線の曲がり位置の手での調整はまだない（必要になったら配置に経路を保存する）。

## 行番号と接点の所在

- 段は用紙の上端から 30mm を 1 段目とし、15mm 間隔（A3 で 1 枚 15 段）。行番号は全シートの通し番号（2 枚目は 16 段目から）。
  記号の段は、配置の基準点（y）がいちばん近い段。
- コイルの下に、その機器の接点がある行番号を a / b / c 接点に分けて書く（例: `a:2,3 b:5 c:7`。主接点は a に含める）。
- 接点の下には、コイル（サーマルリレーなら熱動素子）のある行番号を書く。どちらも配置から自動で求める。

## 図面 JSON への保存（`schematic`）

展開図の配置は概念図と同じ図面 JSON の任意キー `schematic` に保存する。無ければ展開図は未作成とみなす。
座標はシート上の mm（左上原点・下向き正。画面と同じ向き）。

```json
"schematic": {
  "settings": { "paper": "A3" },
  "sheets": [
    {
      "id": "D1",
      "name": "制御回路",
      "rails": { "left": "PSU1.+V1", "right": "PSU1.-V1" },
      "items": [
        { "element": "ES1:21-22", "x": 60, "y": 30 },
        { "element": "MC1:A1-A2", "x": 330, "y": 30 },
        { "element": "MC1:13-14", "x": 60, "y": 45, "rotation": 90 }
      ]
    }
  ]
}
```

| キー | 説明 |
|---|---|
| `settings.paper` | 用紙（`A3` / `A4`。横置き。既定は A3）。配置の格子は 2.5mm |
| `sheets[].kind` | 省略時は展開接続図（記号を置く）。`"terminal"` は端子台接続図（表を自動で作る。`items` は使わない） |
| `sheets[].blocks` | 端子台接続図にする端子台の機器名（省略時は図面のすべての端子台） |
| `sheets[].rails` | 左右の母線にする網（`機器名.端子ID`。その端子とつながった網全体）。左が電源側（+V・R など）、右が戻り側（0V・S など） |
| `sheets[].items` | 配置した要素。`element` は要素 ID、`x` / `y` は記号の基準点（2 端子の記号なら端子 1）、`rotation` は反時計回りの 0 / 90 / 180 / 270 |

- 型と読み書きは `src/schematic/model.ts`（`parseSchematic()` は壊れた部分を読み飛ばす）。
- `flip: true` は、記号の向きはそのままで端子 1 と 2 を入れ替えて置く（2 端子の記号だけ。端子番号の表示も入れ替わる）。
  逆向きに回転すると文字が逆さになるため、接点を右から左へたどるときなどはこちらを使う（エディタでは F キー）。
- 1 つの要素はどれか 1 つのシートに 1 回だけ置く。どこにも置いていない要素はエディタの一覧に「未配置」として出る。
- 概念図の機器を消すとその要素の配置も消え、機器名を変えると配置の要素 ID と母線の指定も変わる。
- I/O 割付図は展開接続図のシートに自動配置で段を並べて作る（専用のシートの種類は持たない）。

## 展開図 JSON（Python への受け渡し: `conneko-schematic`）

アプリの「展開図を書き出し」で出力する。座標・記号・線・文字をすべて解決済みにし、Python 側は DXF に写すだけにする。
**座標は mm、DXF と同じ向き（各シートの左下原点・上向き正）** にして、Python 側で座標変換をしない。

```json
{
  "format": "conneko-schematic",
  "version": 1,
  "unit": "mm",
  "title": "搬送コンベア制御盤",
  "revision": "A",
  "layers": {
    "FRAME": { "color": 7 },
    "SYMBOL": { "color": 7 },
    "WIRE": { "color": 7 },
    "WIRENO": { "color": 3 },
    "TAG": { "color": 2 },
    "TEXT": { "color": 7 }
  },
  "symbols": {
    "contact-no": {
      "description": "a 接点",
      "primitives": [
        { "kind": "line", "points": [[0, 0], [3, 0]] },
        { "kind": "line", "points": [[3, 0], [7.33, 2.5]] },
        { "kind": "line", "points": [[7, 0], [10, 0]] }
      ],
      "pins": { "1": [0, 0], "2": [10, 0] },
      "attributes": [
        { "tag": "T1", "at": [1.5, 1.5], "height": 1.8, "align": "center" },
        { "tag": "T2", "at": [8.5, 1.5], "height": 1.8, "align": "center" },
        { "tag": "TAG", "at": [5, -4], "height": 2.5, "align": "center" },
        { "tag": "XREF", "at": [5, -6.5], "height": 1.8, "align": "center" }
      ]
    }
  },
  "sheets": [
    {
      "id": "D1",
      "name": "制御回路",
      "paper": { "width": 420, "height": 297 },
      "inserts": [
        { "symbol": "contact-no", "at": [60, 257], "rotation": 0, "layer": "SYMBOL",
          "attributes": { "TAG": "MC1", "T1": "13", "T2": "14", "XREF": "12" }, "element": "MC1:13-14" }
      ],
      "polylines": [
        { "points": [[20, 257], [60, 257]], "layer": "WIRE", "wire": "W12" }
      ],
      "dots": [{ "at": [40, 257], "layer": "WIRE" }],
      "texts": [
        { "at": [45, 259], "text": "101", "height": 2.5, "align": "center", "layer": "WIRENO" }
      ]
    }
  ]
}
```

- `layers` はレイヤーの名前と色（AutoCAD の色番号）。社内の決まりはないので、Conneko の既定として次の 6 つにする。

  | レイヤー | 色 | 内容 |
  |---|---|---|
  | `FRAME` | 7（白/黒） | 図面枠・表題欄・行番号 |
  | `SYMBOL` | 7（白/黒） | 記号 |
  | `WIRE` | 7（白/黒） | 線・母線・接続点 |
  | `WIRENO` | 3（緑） | 線番 |
  | `TAG` | 2（黄） | 機器名・端子番号・接点の所在（記号の属性） |
  | `TEXT` | 7（白/黒） | その他の文字（コメントなど） |

- `symbols` は記号の定義（DXF のブロックになる）。図形は `line`（折れ線。`closed` で閉じる、`dashed` で破線）/ `circle` /
  `arc`（中心・半径・開始角・終了角[度]、反時計回り）/ `text`（固定の文字）の 4 種類だけにする。
  `pins` は端子の位置（参照用）、`attributes` は配置ごとに変わる文字（DXF の属性）。
- 文字の `at` は文字の高さの中央で、`align`（`left` / `center` / `right`）で左端・中央・右端のどれを合わせるかを決める。
- 型は `src/schematic/format.ts`。見本は `tools/dxf/samples/sample.json`（`npm run schematic-sample` で作る）。
- `sheets[].inserts` が記号の配置（DXF の INSERT）、`polylines` が線、`dots` が接続点（T 字の黒丸）、`texts` が線番・行番号・図面枠の文字など。
- 図面枠・表題欄も `polylines` と `texts` で渡す（Python 側に図面枠の知識を持たせない）。
- シートごとに 1 つの DXF ファイルを出すか、1 ファイルに並べるかは Python 側のオプションにする。

## Python スクリプト（`tools/dxf/`）

- 使い方は [tools/dxf/README.md](../tools/dxf/README.md)。
- `ezdxf` で展開図 JSON を読み、レイヤー → ブロック（`symbols`）→ 各シートの INSERT・線・文字の順に書く。
- 書き出した DXF は IJCAD で開く。IJCAD は AutoCAD 互換なので、DXF は AutoCAD 2013 形式（R2013。文字は UTF-8）とし、
  文字スタイルは日本語の出る TrueType フォント（MS ゴシック）にする。段階 2 で実際に IJCAD で開いて、文字化け・属性・ブロックの扱いを確かめる。
- 機器定義・接続・記号の形を一切持たない（200 行ほど）。
- 確認: 見本の展開図 JSON から DXF を作り、`ezdxf` の監査（audit）でエラーがないこと、PNG に描画して見た目を確かめる。
  最後に IJCAD で開いて確かめる。

## エディタ（Conneko の別モード）

実装は `src/editor/SchematicEditor.tsx`。

- ツールバーで「概念図 / 展開図」を切り替える。展開図はシートのタブを概念図とは別に持つ（初めて開くと 1 枚作り、母線を電源の出力から選んでおく）。
- 左: 要素の一覧（機器ごと。記号の小さなプレビューつき。検索・配置済みも表示の切り替え）。用紙へドラッグするか、ダブルクリックで置く
  （ダブルクリックはコイル・表示灯・電動機を右の母線の近く、それ以外を左の母線の近くの、空いている最初の段に置く）。
- 中央: 用紙と 5mm の目盛り。記号はドラッグで移動（2.5mm の格子に吸着）、R で回転（Shift+R で逆）、矢印キーで 2.5mm（Shift で 10mm）、
  Delete で外す。ホイールでカーソルの位置を中心に拡大・縮小、空いているところ（用紙の外を含む）のドラッグで表示を動かす（概念図と同じ操作）。
  線は配置を変えるたびに引き直す。
- 右: 選んだ記号の情報（機器・端子と記号の端子の対応・行番号、回転、展開図から外す、概念図で表示）。
  何も選んでいなければシートの設定（左右の母線・用紙）、「自動で並べる」（下の「自動配置」）、展開図 JSON の書き出し。
- F キー（または右のパネルの「端子を入れ替え」）で、2 端子の記号の左右の端子を入れ替える。
- 記号は展開図 JSON と同じ図形定義から SVG で描く（`sheetSvgBody()`。プレビューと DXF が一致する）。
- 元に戻す・やり直す、保存・読み込みは概念図と共通（展開図の配置も図面 JSON に入る）。出力メニューからも展開図 JSON を書き出せる。
- サンプル図面に見本の配置（主回路、表示灯と PLC の出力）がある。

## 自動配置

実装は `src/schematic/autoLayout.ts`（`autoLayout()`）。エディタの右のパネルの「自動で並べる（未配置の段）」から使う。置いた記号は動かさない。

- 左の母線の網から、接点・コイル・表示灯・PLC の入出力点を辺としてたどり、右の母線の網か PLC の入出力点に着く経路を探す
  （置いていない端子台などは網として素通しになる）。
- 行き着く記号（コイル・表示灯・入出力点）ごとに 1 段にする。いちばん短い経路を本線として左（x = 60）から 10mm 間隔で並べ、
  行き着く記号は段の右端に置く。ほかの段と共通の接点（非常停止など）は一度だけ置き、次の段はその右から続ける。
- 本線の一部を迂回する経路（自己保持の接点など）は、分かれる位置の本線の記号の真下の段に置く。
- 経路を逆向きに通る記号は `flip` で端子を入れ替える（自己保持の a 接点を 14-13 の向きで置くなど）。
- 接点でたどれない PLC の入出力点で、電源を母線からもらう機器（3 線式センサーなど）の箱につながるものは、
  箱を左、入出力点を右端（箱の出力の端子と同じ高さ）に置いて 1 段にする（I/O 割付図）。
- 段の高さは、置く記号の上への張り出しが、すでに置いた記号の外形と重ならない最初の段。

## 端子台接続図

`kind: "terminal"` のシートは、記号を置かず、端子台（`category: 'terminal'` の機器）ごとの表を概念図の接続から自動で作る
（`src/schematic/layout.ts` の `terminalPages()`）。エディタでは展開接続図のシートの設定にある「端子台接続図のシートを追加」で作り、表にする端子台を選ぶ。

- 列は「接続先｜線番｜端子｜線番｜接続先」。左は端子の 1 側（上段のネジ・ネジ端子）、右は 2 側（下段のネジ・MIL などのコネクタ）。
- 接続先は `機器名.端子ID（印字）`（長いときは端子 ID だけ）。相手がリンクなら「リンク『名前』」。コネクタ側はケーブルでつながったピンと、ケーブル名を線番の欄に書く。
- 表は用紙の左上から列（A3 で 2 列）に流し、収まらなければ次の列・次のページへ続ける（見出しに「（続き）」）。
  1 枚のシートが複数のページになるときは、展開図 JSON のシート ID を `D3`、`D3-2`… とし、`source` に元のシート ID を書く。
- 行番号は展開接続図のシートだけで数える。図面枠のページ番号は全ページの通し。

## 決めたこと

| 項目 | 決定 |
|---|---|
| DXF を開く CAD | IJCAD。DXF は AutoCAD 2013 形式（UTF-8）、文字は MS ゴシック |
| 記号の規格 | JIS C 0617（IEC 60617 と同じ記号）。古い JIS C 0301 の記号は使わない。コイルは四角（JIS C 0301 の丸ではない） |
| 展開接続図の形 | 左右に縦の母線、その間に横向きの段を上から並べる（PLC のラダー図と同じ形。横書き） |
| レイヤー | 社内の決まりはないので、上の「展開図 JSON」に書いた 6 つを既定にする |

## 決めること（未決）

実際の図面で使いながら決める。

- 段の高さ・用紙（今は A3 横・格子 2.5mm・段の高さ 15mm。操作部つきの接点は上に 5mm ほど、機器名と接点の所在は下に 7mm ほど出るので 10mm では重なる）。
- 記号の細部（リミットスイッチ・引き操作の操作部の形、直接開路動作の印、セレクタスイッチ・タイマー接点の記号、回転した記号の文字の向き）。
- 線番の表示位置（今は最も長い横の区間の上）と、端子台の端子を展開図に描くかどうか。
- ソース出力（PNP）のように PLC の出力を段の左に置く場合の記号（今は回転で対応し、文字が逆さになる）。
- 線の曲がり位置の手での調整、母線への引き出しが記号を横切る場合の回避。
