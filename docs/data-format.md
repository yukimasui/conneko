# 図面データ（JSON）の形式

Conneko の図面は次の形式の JSON で保存・読み込みする。生成AIに編集させることを想定し、単純で自己記述的な構造にしている。
型定義は `src/model/diagram.ts`。

```json
{
  "format": "conneko-diagram",
  "version": 1,
  "devices": [
    { "id": "PS1", "type": "generic.power-source.3p200v", "x": 100, "y": 0 },
    { "id": "ELB1", "type": "mitsubishi.nv32-sv.3p", "x": 40, "y": 180, "params": { "ratedCurrent": 20 } }
  ],
  "wires": [
    {
      "id": "W1",
      "from": { "device": "PS1", "terminal": "R" },
      "to": { "device": "ELB1", "terminal": "1" },
      "wireNo": "R",
      "color": "black",
      "sizeSq": 3.5,
      "wireType": "KIV"
    }
  ]
}
```

## devices（機器）

| キー | 必須 | 説明 |
|---|---|---|
| `id` | ○ | 機器名。図面内で一意（例: `ELB1`）。空白と `.` は使えない |
| `type` | ○ | 機器種別。`src/devices/catalog/` の各定義の `type` |
| `x`, `y` |  | キャンバス上の位置（左上, px）。省略時は自動で並べる |
| `params` |  | 機器パラメータ（定格電流など）。キーと選択肢は機器定義の `params`。装着していない I/O ユニットの先頭番号は `ioIn` / `ioOut`（点数）で指定できる |
| `mount` |  | 増設ユニットの連結・ベースユニットへの装着。`{ "device": 親の機器名, "slot": 位置（1 から） }` |
| `sheet` |  | 配置するシートの id（`sheets`）。省略時は最初のシート |
| `comments` |  | 端子・ピンごとのコメント（PLC の入出力の用途など）。`{ "CN1#1": "PH1 ワーク検出" }` |
| `note` |  | 機器のコメント（何をするものか。例: `"ワーク検出（コンベア入口）"`） |

### シートとリンク

図面は回路の意味ごとにシート（タブ）に分けられる。

```json
"sheets": [{ "id": "S1", "name": "主回路" }, { "id": "S2", "name": "PLC" }]
```

- 電線は同じシートの機器どうしだけをつなぐ。別のシートへは **リンク**（`type: "generic.link"`）を両方のシートに置き、
  同じ名前（`params.name`）にしてそれぞれ電線でつなぐ。名前が同じリンクどうしは導通する（同じシートの中で使ってもよい）。
  `params.side` は電線をつなぐ側（`"auto"`（既定。つないだ相手の端子のある側）/ `"left"` / `"right"`）。
- シートをまたぐ電線を書いて読み込んだ場合は、アプリが自動で両端にリンクを置いた形に置き換える。
- 相手のいないリンク・名前のないリンク・電線のつながっていないリンクは警告する。
- LAN ケーブルには **ネットワークリンク**（`type: "generic.network-link"`、端子 `LAN`）を使う。名前が同じネットワークリンクに LAN ケーブル
  （`wireType: "CABLE"`）でつないだ機器どうしは、同じネットワーク（スイッチングハブでまとめたもの）にあるとみなす。
  電線用のリンクとは名前の空間が別。ネットワークにある通信ポートどうしで共通の通信方式（`connector.protocols`）がなければ警告する。
  シートをまたぐ LAN ケーブルも、読み込み時にネットワークリンクの組に置き換える。

### 装着（mount）

CPU の右に連結する増設ユニットや、ベースユニットに装着するユニットは `mount` で親を指定する。

```json
{ "id": "PLC1", "type": "keyence.kv-8000.cpu", "x": 600, "y": 0 },
{ "id": "IN1", "type": "keyence.kv-c32xc.input", "x": 0, "y": 0, "mount": { "device": "PLC1", "slot": 1 } },
{ "id": "OUT1", "type": "keyence.kv-c32tc.output", "x": 0, "y": 0, "mount": { "device": "PLC1", "slot": 2 } }
```

- 装着したユニットは親の横（ベースユニットなら上）に位置の順で並べて描く（`x` / `y` は無視される）。
- 入出力の先頭番号は位置の順に自動で割り付けられ、端子・ピンの名前に反映される。
- 親と同じ系列（バス）のユニットだけを装着できる。スロット数・内部電源（5V など）の消費電流の合計もチェックする。

電磁弁のマニホールドも同じ書き方をする。親がマニホールドベース、装着した機器 1 台が 1 連（ベース配管形の電磁弁またはブランクプレート）で、`slot` が連の番号（1 が D 側＝左）。

```json
{ "id": "MF1", "type": "smc.ss5y3-41", "x": 300, "y": 0 },
{ "id": "SOL1", "type": "smc.sy3140-5lz", "x": 0, "y": 0, "mount": { "device": "MF1", "slot": 1 }, "params": { "portAB": 6 } },
{ "id": "SOL2", "type": "smc.sy3240-5lz", "x": 0, "y": 0, "mount": { "device": "MF1", "slot": 2 } },
{ "id": "BP1", "type": "smc.sy3000-26-9a", "x": 0, "y": 0, "mount": { "device": "MF1", "slot": 3 } }
```

- マニホールドの型式（例: `SS5Y3-41-03-C6`）の連数・A/B ポートの継手は、装着した連から自動で決まる（params に書かない）。
- 装着した電磁弁の P・EA・EB はマニホールドの中で SUP（`P`）・EXH（`EA`・`EB`）につながるので、チューブはつながない。
  エア源からマニホールドの `P` へ、各電磁弁の `A`・`B` からシリンダなどへチューブでつなぐ。ソレノイドは各弁のリード線（`A+`・`A-`・`B+`・`B-`）に電線でつなぐ。

## settings（図面の設定）

| キー | 説明 |
|---|---|
| `requiredPL` | 安全機能に要求するパフォーマンスレベル（ISO 13849-1。`"a"`〜`"e"`）。これを下回る安全機器を警告する |
| `title`, `author`, `revision` | 図面名・作成者・版（印刷の図面枠に入る） |

## wires（電線）

| キー | 必須 | 説明 |
|---|---|---|
| `from`, `to` | ○ | 接続する端子 `{ "device": 機器名, "terminal": 端子ID }`。`"ELB1.1"` のような文字列でもよい |
| `id` |  | 電線ID（例: `W1`）。省略・重複時は自動採番 |
| `wireNo` |  | 線番 |
| `color` |  | 電線色ID（`src/data/wires.ts` の `WIRE_COLORS`）。既定は `DEFAULT_WIRE` |
| `sizeSq` |  | 太さ（公称断面積 mm²） |
| `wireType` |  | 電線の種類ID（`src/data/wires.ts` の `WIRE_TYPES`） |
| `bend` |  | 配線の曲がり位置の調整量[px]。ユーザーが手で調整した場合のみ |
| `route` |  | 手で曲げた経路（両端の端子から少し出た点どうしの間の頂点 `[{ "x", "y" }, …]`）。ユーザーが手で曲げた場合のみ |
| `fromSide`, `toSide` |  | 端子から電線を出す向き（`"top"` / `"bottom"` / `"left"` / `"right"`）。省略時は自動（端子の向き。相手がリンクなら左右はリンクのある側） |

電線に向きはない（`from` と `to` を入れ替えても同じ）。1つの端子に複数の電線をつないでもよい（渡り配線）。

### ケーブル（コネクタ間の接続）

MIL コネクタや LAN ポートなど、`role: 'connector'` の端子どうしはケーブルでつなぐ。ケーブルも `wires` の1要素として書き、
`wireType` を `"CABLE"` にする（`color` / `sizeSq` は使わない。`wireNo` はケーブル名として表示される）。

```json
{ "from": { "device": "IN1", "terminal": "CN1" }, "to": { "device": "TB2", "terminal": "CN" }, "wireType": "CABLE", "wireNo": "CBL1" }
```

- 同じ種類（`connector.kind`）のコネクタどうしだけをつなげる。変換ケーブルがある組み合わせ（三菱 FCN40 と MIL40 など、機器定義の `connector.mates`）もつなげる。
- 通信ポートは、両端に共通の通信方式（`connector.protocols`。Ethernet と EtherCAT など）がないと警告する。
- ケーブルでつなぐと、両端の同じ番号のピンどうしが導通する（例: PLC 側 `CN1#1` ↔ 変換端子台側 `CN#1`）。
- MIL ケーブルは、コネクタ付近で色付きの芯線が広がり黒いシースにまとまる多芯ケーブルとして描画される。M8 / M12 の丸形コネクタは灰色のセンサーケーブルとして描画される。

### チューブ（エア配管）

エアのポート（端子の役割が `air`）どうしは、チューブでつなぐ。チューブも `wires` に電線と同じ形で書き、次の項目を使う。

| キー | 説明 |
|---|---|
| `wireType` | チューブの種類ID。`TU`（ポリウレタンチューブ、最高使用圧力 0.8MPa）・`T`（ナイロンチューブ、1.0MPa） |
| `tubeOD` | チューブの外径[mm]（4 / 6 / 8 / 10 / 12）。ポートの適合チューブ外径と違えば警告する |
| `color` | チューブの色ID（`blue`・`black`・`white`・`clear`・`red`・`yellow`・`green`・`orange`） |
| `sizeSq` | 使わない（0） |
| `wireNo` | 配管番号（任意） |

```json
{ "from": { "device": "SOL1", "terminal": "A" }, "to": { "device": "CY1", "terminal": "HEAD" }, "wireType": "TU", "tubeOD": 6, "color": "blue", "sizeSq": 0 }
```

- エアのポートどうしを `wireType` や `tubeOD` を省いて書いた場合は、読み込み時にポリウレタンチューブ・ポートの適合外径に補う。
- エアのポートと電気の端子をつなぐと誤りとして指摘する。
- 別のシートへは、エアのリンク（`generic.air-link`、端子 `T`）を両方のシートに置き、同じ名前にしてチューブでつなぐ。電線のリンクとは名前の空間が別。
- チェックでは、エア源（`generic.air-source` など）の供給圧力から、レギュレータの設定圧力・電磁弁の切り換えを通って各ポートの圧力を求め、使用圧力範囲・チューブの最高使用圧力・未接続のポート・エアの届かない機器・排気ポートへの給気を指摘する。
- 真空のポート（エジェクタの `V`、吸着パッド、真空用圧力スイッチ）どうしもチューブでつなぐ。真空は圧力の計算の対象外で、真空の配管の途中の継手はエアが届かなくても指摘しない。
- スピードコントローラは、記号の `in` → `out` が自由流れ。インライン形（`smc.as-f.inline`）はメータアウトなら `IN` を電磁弁側、`OUT` をシリンダ側につなぐ。エルボ形は `CYL`（おねじ）をシリンダのポートに、`TUBE` を電磁弁側につなぐ（`smc.as2201f` がメータアウト、`smc.as2211f` がメータイン）。

## schematic（展開図の配置）

展開図を作ると、記号の配置が任意キー `schematic` に入る。接続は持たず（`devices` / `wires` から求める）、置いた位置だけを持つ。
詳しくは [schematic-dxf.md](schematic-dxf.md) の「図面 JSON への保存」。

```json
"schematic": {
  "settings": { "paper": "A3" },
  "sheets": [
    {
      "id": "D1",
      "name": "制御回路",
      "rails": { "supply": "PSU1.+V1", "common": "PSU1.-V1" },
      "items": [{ "element": "MC1:A1-A2", "x": 330, "y": 30 }]
    }
  ]
}
```

- `kind` のあるシートは内容を自動で作る: `"terminal"` 端子台接続図（`blocks` に端子台の機器名を書くとそれだけ）、`"io"` PLC の I/O 図（`plc`・`units`）、
  `"rack"` PLC のユニット構成図（`plc`）、`"bom"` 部品表、`"cover"` 表紙・図面目次。`paper` でシートごとに用紙（`"A3"` / `"A4"`）を変えられる。
- `element` は `機器名:キー`（コイル `A1-A2`、接点 `13-14`、遮断器などの極 `main`、PLC の入出力点はピン ID など）。座標は用紙上の mm（左上原点・下向き）。
- 生成AIに図面を渡すときは、`schematic` はそのまま残すか、削除してもよい（削除すると展開図の配置がなくなる）。

## 生成AIとのやりとり

1. アプリの「AI用にコピー」で、指示文・使用中の機器の端子一覧・現在のチェック結果・図面JSON をまとめてクリップボードにコピーする。
2. ChatGPT や Claude に貼り付け、返ってきた JSON をアプリの「JSONを貼り付け」で読み込む（```json のコードブロックのままでよい）。
